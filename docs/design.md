# Design and interaction

Paths in this document are relative to the repository root. For data contracts and repository calculations, see [architecture.md](./architecture.md).

## Design tokens (`src/index.css` → `@theme`)

| Token | Value | Use |
|---|---|---|
| `bg-page` | `#f5f0e6` | page background (warm beige) |
| `bg-card` | `#f8f3ea` | cards — slightly LIGHTER than page |
| `bg-section` | `#ebe3d2` | tag pills / recessed fills (deepest) |
| `border-warm` | `#e3dac6` | hairline borders |
| `text-primary` | `#1f2329` | body text |
| `text-secondary` | `rgba(0,0,0,.55)` | muted text |
| `font-serif-main` | Georgia stack | display type (blog empty state); the hero name uses Allura and `GithubLink` uses Kalam |
| `font-mono-num` | Geist Mono stack | numbers, dates, repo names |
| `ease-out-strong` | `cubic-bezier(.16,1,.3,1)` | the house easing — use it for all motion |
| `radius-card` | `4px` | cards, panels, article blocks |
| `radius-chip` | `3px` | buttons, tags, pills, badges |
| `radius-hair` | `2px` | heatmap cells, bars, legend swatches |
| `radius-round` | `999px` | avatars only |

Layering rule: `bg-section` (darkest) < `bg-page` < `bg-card` (lightest). Never use pure white (`bg-white`) for surfaces.

Radius rule: the site is squarish, so nothing is a pill. Use the tokens (`var(--radius-card)` in CSS, `rounded-card` / `rounded-chip` in Tailwind) rather than literal values, and keep `radius-round` for avatars alone — they are the only circular element.

## Homepage layout

- Home shares a 960px `.site-frame` and one left alignment line. Hero uses a self-hosted Allura signature name beside a subtle 300px particle portrait; on mobile the smaller portrait remains beside the name. The nav is sticky (`sticky top-0 z-50`) on an opaque `bg-page` surface with a single hairline `border-b` spanning the full viewport width; the footer carries no divider and only the `.footer-sign` copyright, right-aligned in the same Kalam face as `GithubLink` so the two handwritten moments bookend the page. Every nav item is plain text at one weight and colour, including the GitHub link — no filled or outlined button in the nav. The entry for the page on screen carries `aria-current="page"`, and `.nav-link[aria-current='page']` turns it to `text-primary` and holds the same 1px underline open permanently, so the current page and the hover gesture read as one system. The GitHub link deliberately has no `nav-link` class and is never marked as current.
- Every link that leaves the site ends with `ExternalArrow`, a self-drawn SVG rather than the `↗` glyph: a glyph's shaft length is baked into whichever font draws it, so it could not be shortened on request. The SVG keeps the ink inside a `1em` square (`viewBox 0 0 10 10`) whose **bottom edge sits on the baseline**, at the same offsets the glyph's ink used to occupy (top 0.739em above the baseline, bottom 0.019em below), so an inline host keeps the historical `top: -0.42em` and lands in exactly the same place. It is `aria-hidden`, `position: relative` (so it never changes the host's height) and sized `max(0.55em, 7px)`. Two traps: (1) an `em` in `top` resolves against the **arrow's own** font-size, not the host's; (2) when the host is a flex container the box bottom no longer lands on the baseline, so the offset must be recomputed per host — `.gh-link` (17px host, 7.14px arrow) uses `-0.67em` and `.obs-tags` (11px host, 7px arrow) uses `-0.59em`, each reproducing the old glyph-era position. Keep the host's `gap` at `2px` — the component supplies the rest of the spacing.
- Every in-site jump to GitHub goes through `GithubLink` (`src/components/GithubLink.tsx`): the label is fixed at `profile.nav.github` in the Kalam handwritten font and only the `href` varies. It is used by the nav and the observatory's per-repository entry, so a GitHub entry looks identical everywhere. Add new GitHub entries with this component instead of a hand-written anchor. Its `font-size` is set by the **ink height**, not by eye: Kalam's ink is about 88% of its font-size, so `17px` renders the word about 15px high against the nav's 13px text — raising it further makes the nav entry shout over the menu.
- `--nav-h` (72px, in `@theme`) is the single source of truth for the sticky nav's total height — `box-sizing: border-box` keeps the hairline inside it. Everything that scrolls a target into view must clear the bar: home section headings use `scroll-mt-[var(--nav-h)]`, article `h2` use `calc(var(--nav-h) + 24px)`, and `.article-toc` sticks at that same `calc(var(--nav-h) + 24px)`.
- Home order is Hero → 开源作品 → 博客 → 履历. Blog and projects have headers above their content. Home blog entries use warm `bg-card` surfaces; projects use two columns of flat warm cards (one column below 640px). No section divider lines or subtitles. Preserve full descriptions and total counts. Projects display all entries; the home blog still shows up to five posts.
- A blog entry is a single `<a class="blog-row">` wrapping its own date/category, `<h3><span class="blog-title">` and excerpt — clicking anywhere in the row opens the post, exactly like `RepoCard`. Hovering anywhere in the row (not just the title text) turns the surface `#eee7d9` and underlines `.blog-title`, so the title feedback and the row feedback are one gesture. The archive reuses `.blog-row` as an editorial hairline list instead of cards: the row bleeds 16px into the frame gutter (`padding-inline: 16px; margin-inline: -16px`), the separator moves to an inset `::after` so it stays frame-wide while the hover fill bleeds, and hover fills with `bg-card`. Because `.blog-row` now declares its own `transition`, it must list `opacity` and `transform` alongside `background` — otherwise it would override `.reveal`'s transition and break the scroll fade-in.
- Work and education share one 履历 grid: a single list over `profile.experience`, two items per row (one column below 640px), each entry a `bg-card` card with a `experience-kind` pill (`profile.experienceKinds`) marking 工作 or 教育 beside its dates. No timeline ornaments.
- 观测 is not on the home page. It mirrors the blog archive: a full page with the section heading at 32px and a repository switcher (pill links on `bg-card`, active one on `bg-section`) above the observatory column. Neither top-level page carries a back link — the sticky nav already marks the current page with an underline, so `.back-link` exists only inside an article, where it returns to the blog list rather than the home page.
- The observatory reuses the card ink palette rather than GitHub's greens: the heatmap is five steps of `rgba(31,35,41,…)` (`.16 / .32 / .55 / .82`) on `bg-section`, and the language bar is one ink at decreasing opacity. Levels come from quartiles of the non-zero days (`heatThresholds`), so one 468-commit day cannot flatten every other day into a single shade.
- `src/lib/repoActivity.ts` holds the observatory's arithmetic — `activityStats`, `alignWeeks`, `movingAverage`, `monthLabels`, `rhythmStats`, `quietWindow`, `medianReleaseInterval`, `contributorShare`, `relativeTime`, `releaseTitle`, `formatBytes`, `formatSize`, `formatCompact`, `formatShare`, `daysSince` — and stays free of React and `import.meta.env` so `npm run test:metrics` can load it directly under Node.
- The heatmap is a CSS grid sized by an inline `--obs-weeks` (53 after `alignWeeks`, so recent data lands at the right edge): cells are capped at 25px. Young repositories still occupy all 53 columns, with zero-weeks prepended on the left. `.obs-calendar-wrap` is a wrapping flex row, which lets the calendar and its footer stats share a line when the calendar is narrow and stack when it fills the width. On mobile the grid switches to `minmax(11px, 1fr)` with `overflow-x: auto`.
- The weekly panel draws one bar per week plus a 3-week moving average as a `preserveAspectRatio="none"` SVG polyline with `vectorEffect="non-scaling-stroke"`; the language panel's rows report bytes and percentages, and the segments deliberately do not fill the bar.
- 提交节律 is a 25-column grid (weekday labels + 24 hours) with a 168-cell body; the quiet band is an absolutely-positioned grid item spanning the quiet hours across all seven rows, so it sits behind the cells. On mobile its columns bottom out at `minmax(20px, 1fr)` and scroll, keeping the hour labels legible. 节律读数 is a two-column definition list of five readings. 贡献者 rows are a six-column grid (rank, avatar, name, share bar, count, percentage) whose bar and percentage drop on mobile. 发布节奏 pairs a tick strip positioned over the release-time span with a list of the newest versions, and 最近提交 lists the newest commits with short-sha links. 发布节奏 and 最近提交 both reflow to two rows on mobile.

## Interaction system

- **Hero portrait**: `HeroParticles` samples `public/images/hero-portrait.jpg` into Canvas 2D particles. Dark pixels form the portrait while light pixels leave the beige background visible. An explicit character outline excludes the floral background from sampling. Mouse proximity scrambles nearby particles in different directions with bounded displacement; springs bring them home without creating a radial hole. Native cursor throughout; no quote invert mask or globe. Touch and reduced-motion modes render a static portrait. Rendering pauses when settled, offscreen, or hidden.

- **Hover underlines**: `.nav-link` and the shared `.sweep-underline` draw their 1px underline as a `linear-gradient(currentColor, currentColor)` background whose `background-size` animates from `0 1px` to `100% 1px` — the nav is anchored at `50% 100%` so it opens from the middle outwards, `.sweep-underline` at `0 calc(100% - var(--sweep-gap))` so it sweeps left to right. A background is used instead of `::after` because every host is an **inline or fit-content** box: an absolutely positioned pseudo-element would size to the containing block rather than to the text run. `box-decoration-break: clone` gives each wrapped line its own sweep. `.sweep-underline` is worn by the blog title (`.blog-title`, `--sweep-gap: 3px`) and by the observatory card title (`.starred-head h3`, `--sweep-gap: 4px`); the gap is measured per font — it is what lands the line the right distance below the baseline, so recompute it if a host's font size or line-height changes. Two traps: (1) the hover trigger must sit on the row, not the title, so `.blog-row:hover .blog-title` and `.starred-card:hover .starred-head h3` are what flip the size; (2) any Tailwind `transition-*` utility on `.nav-link` overrides the rule's own `transition` shorthand and silently kills the animation, which is why the class string is just `nav-link hover:text-text-primary`.
- **Reveal on scroll**: add class `reveal`; stagger via inline `transitionDelay`.
- **Article navigation**: `useActiveSection` tracks the current H2 while scrolling and after content resizing; desktop and mobile contents share the hover style through `aria-current="location"`. Article pages show a floating `BackToTop` button after 400px, with keyboard focus restoration and reduced-motion support.
