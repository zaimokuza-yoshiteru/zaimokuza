# Architecture and maintenance

Paths in this document are relative to the repository root. For commands and working conventions, see [AGENTS.md](../AGENTS.md); for visual behavior, see [design.md](./design.md).

## Structure

- `src/data/profile.ts` — single source of truth for ALL copy (hero greeting and name, portrait description, project use-case descriptions, social links, experience timeline). Edit this file to change site content; the `Profile` interface documents the shape.
- `scripts/lib/repo-metrics.ts` — the shared build-time collector behind both JSON snapshots. Ordinary API failures abort before writing; statistics returning `202` with `{}` retry five times, five seconds apart. Unavailable statistics warn and retain the same repository's prior samples via `readPrevious`; successful empty responses clear them. Only a 404 from the latest-release endpoint falls back to the release list. CLI calls use a 30-second timeout and a 64 MB `maxBuffer`; snapshots replace their destination atomically after collection finishes.
- `src/data/projects.json` — generated by `scripts/fetch-github.ts`; do not hand-edit.
- `src/data/starred.json` — generated by `scripts/fetch-github-starred.ts`; do not hand-edit. Both snapshots are refreshed on a schedule and read by the browser at runtime, so their shape is a public contract: change a field and you must change `src/lib/repoSource.ts` with it.
- `src/components/` — `Nav`, `Hero`, `HeroParticles`, `Blog`, lazy-loaded `BlogArticle`, shared `SectionHeader`, shared `RepoCard` / `RepoFacts`, `Projects`, `Starred`, `RepoObservatory`, shared `GithubLink` / `ExternalArrow`, `Experience`, `Footer`.
- Blog metadata and shared UI copy live in `profile.blog` / `profile.articleUI`; posts use unique stable slugs, ISO dates and excerpts, sorted newest first. Long-form copy lives in `src/data/articles/<article>.md`, selected by each post's required `article` key. Home shows up to five posts; `#/blog` shows all, and `#/blog/<slug>` renders an article. `src/lib/navigation.ts` prefixes links with the deployment base.
- 观测 is its own page rather than a home section: `#/starred` opens the first curated repository, `#/starred/<owner>/<repo>` deep-links one, and the repository list above the observatory switches between them (`aria-current="page"` marks the open one). `src/lib/navigation.ts` exports `starredHref(fullName?)` for those links.
- Markdown articles render with `react-markdown` and GFM tables. An `example` fenced block containing `q01` through `q09` (plus `q04-cache`) renders Python/TypeScript tabs, copy and downloads from `src/data/articles/examples/`; these standalone teaching programs are excluded from browser TypeScript checking and executed by `test:blog`. Source quotations are verbatim, explained in Chinese, and tracked in `context-management.sources.json`; distinguish them from illustrative implementations. Sketches live in `public/blog/context-management/` and their runtime URLs are base-prefixed. Article dependencies and body load only when opening an article.
- Home displays all projects immediately, with a total in the section heading and no expansion control. Counts derive from data. `useRevealOnScroll` observes dynamically inserted content too.
- `src/interactions.ts` — `useRevealOnScroll` hook (IntersectionObserver adds `.visible` to `.reveal` elements, once).
- `src/index.css` — Tailwind v4 entry; design tokens live in `@theme`.
- `public/fonts/allura-regular.ttf` — signature font, now only for the hero name; its OFL license ships beside it as `public/fonts/allura-OFL.txt`.
- `public/fonts/kalam-regular.ttf` — handwritten font for every GitHub jump (`GithubLink`); its OFL license ships beside it as `public/fonts/kalam-OFL.txt`.
- `public/fonts/geist-mono-regular.ttf` — self-hosted font behind `font-mono-num`; its OFL license ships beside it as `public/fonts/geist-mono-OFL.txt`.
- All three fonts live in `public/` rather than `src/assets/` on purpose: Vite hashes CSS-referenced assets, so a hashed URL can never be written into a `<link rel="preload">` in `index.html`. The matching preloads use `%BASE_URL%`. Keep each preload and CSS URL in sync. Allura and Kalam use `font-display: block`; Geist Mono uses `swap`.
- `.github/workflows/deploy.yml` — builds on push to `main` and publishes `dist` to GitHub Pages.
- `.github/workflows/refresh-starred.yml` — every 12 hours, runs `npm run sync:repos` with `GITHUB_TOKEN`, validates both snapshots with `npm run test:snapshots`, and commits both JSON files together only when changed. It deliberately does **not** rebuild or redeploy: GitHub never triggers workflows from a `GITHUB_TOKEN` push, and this design does not need it to, because the browser reads the file straight from `raw.githubusercontent.com`. The token is an ephemeral installation token minted per run — no secret is stored in the repository.

## Deployment / base path

The site is served from `https://<user>.github.io/zaimokuza/`, so `vite.config.ts` sets `base: '/zaimokuza/'` for `build` and `preview`, and `'/'` for dev. Any runtime URL to a `public/` asset or an internal link MUST be prefixed with `import.meta.env.BASE_URL` (see `portraitUrl` in `HeroParticles.tsx`) — hardcoded leading-slash paths 404 in production.

The three `@font-face` `src: url('/fonts/…')` entries are the deliberate exception: Vite rewrites leading-slash URLs **inside CSS** with `base` at build time (verified as `/zaimokuza/fonts/…` in `dist/assets/*.css`), and `index.html` uses `%BASE_URL%` for the matching preloads. Keep those three pairs in sync — a font URL that does not match its preload href makes the preload a second, wasted download.

## Dynamic GitHub data

- The deployed static page uses `src/hooks/useRepoMetrics.ts` and `src/lib/repoMetrics.ts` to refresh the volatile counters (stars, forks, open issues) of every displayed repository in the visitor’s browser. Cards render the bundled snapshot first. Cache v2 keeps a separate 15-minute timestamp per repository, preserves entries across page changes, and never renews failed entries; 403/429 stops the remaining requests. No token or backend is required.
- 首页 and 观测 re-read `projects.json` and `starred.json` respectively through `src/hooks/useRepoSnapshots.ts` + `src/lib/repoSource.ts`, so a snapshot refreshed by the cron shows up without a redeploy. The bundled file renders first and each fetch only starts on its corresponding page (neither runs on the blog); the fetched data replaces it only if every field validates, so a rate-limited, blocked or malformed response leaves the page exactly as it was. `raw.githubusercontent.com` caches for 5 minutes and sends `access-control-allow-origin: *`; do not switch this to jsDelivr, whose 7-day browser TTL would defeat the refresh.
- `App.tsx` scopes the metrics hook to the page on screen — the pinned works on home, the curated list on `#/starred` — so a visit only refreshes what it can actually display.
- Run `npm run test:metrics` to check caching, staleness, partial and total failure, and the request cap, plus the pure calculations in `src/lib/repoActivity.ts` (streaks, half-over-half trend, heat levels, byte formatting). The fetch scripts generate the metrics; Chinese descriptions live in `profile.projects` / `profile.starred`.

## Repository display (开源作品 · 观测)

- 开源作品 renders the shared card body from `RepoFacts` — a commit-activity sparkline, a language bar with legend, and a telemetry row — inside `RepoCard`, whose whole surface is the link to the repository. 观测 instead renders `RepoObservatory` (`Starred.tsx` adds only the switcher, heading and not-found fallback): a repository hero card, a six-metric strip, and eight numbered panels — 贡献日历, 每周提交量, 语言构成, 提交节律, 节律读数, 贡献者, 发布节奏, 最近提交. Cards stay on scale metrics alone — 最后推送 and the 最近提交 list belong to the observatory, never to a card.
- `RepoCard`'s head is a single `space-between` row: the repository name on the left, the release chip pinned to the top-right. The title carries `min-width: 0` so a long name wraps instead of squeezing the chip, the chip is `flex: 0 0 auto; white-space: nowrap`, and its `margin-top` is the half of the title's line-height minus its own box height that centres it on the title's first line — so the chip reads as a badge on the name rather than a second row. The concrete numbers are 16px / `leading-[1.7]` = a 27.2px line against a 23px chip box, so `margin-top: 2.1px`; `.project-row h3` in `index.css` declares the same size and the two must be changed together, since an unlayered `.project-row h3` silently beats the Tailwind utilities on the element. The head's `gap` is deliberately not reused as the title-to-body spacing; the card's own `gap` still sets that.
- The activity caption and its sparkline sit in a fixed-height block: the box is always reserved, so a repository whose whole life fits one weekly bucket keeps its caption on the same line as its neighbours instead of collapsing the row. The sparkline itself only draws once there are at least two weeks.
- The sparkline is the last N weeks of `/stats/commit_activity`, sliced to the weeks since repository creation so a young repo does not draw a long dead tail. The language bar uses a single ink at decreasing opacity rather than per-language colors; percentages are computed over the total bytes of all languages, so the segments deliberately do not fill the bar. Languages below 0.05% are dropped rather than shown as `0%`.
- 贡献日历 always occupies `CALENDAR_WEEKS` (53) columns: `alignWeeks` prepends zero-weeks before the first real week so recent data sits at the right edge, matching GitHub. All statistics still run on the unpadded array.
- 提交节律 / 节律读数 read `/stats/punch_card` — 168 cells indexed `weekday * 24 + hour`, Sunday first, times UTC, and GitHub caps the sample at the most recent 20,000 commits (so the panel total can be smaller than 贡献日历's). The quietest window is a ring search over every start hour, so it may wrap past midnight; `quietSegments` splits a wrapping window into two grid spans.
- 贡献者 / 发布节奏 / 最近提交 read `/contributors`, `/releases` and `/commits` from the snapshot rather than the API, so the browser never re-fetches them. 发布节奏 hides a release name whose digits match its tag, since most repositories name releases after the tag with a different prefix. 最近提交 links each short sha to `repo.url/commit/<sha>`.
- `repo.release` falls back to the newest pre-release when `/releases/latest` 404s. `ReleaseChip` takes `showPrerelease` (default `true`): 观测 marks that fallback with a `预览版` chip, 开源作品 passes `false` and shows the bare version, because a card is a scale metric rather than a release report. Totals for commits and contributors come from the `Link: rel="last"` page count.
- Shared labels live in `profile.repoUI`; per-section copy is `profile.projects` / `profile.starred`. Add a followed repository by adding it to `WATCHED` and to `profile.starred.entries`; removing it from `WATCHED` drops it from the page. The works list follows the GitHub profile's pinned repositories, so pin or unpin a repository to change it — re-pinning `mcp2skill` or `dsh-plugin-hub` restores their existing descriptions.
