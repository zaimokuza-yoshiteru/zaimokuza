# zaimokuza — personal site

Personal blog of Zaimokuza: a particle portrait opening, blog, open-source works, an observatory for followed repositories, and experience timeline. Warm beige palette, serif display type, and native system cursors.

## Commands

- Use Node.js 24.12+; CI runs Node 24. `npm run typecheck` checks app code and `scripts/**/*.ts` independently with strict settings.
- `npm run sync:repos` — collect both snapshots, validate both with the browser schema, then write both; errors before writing leave both existing files intact.

- `npm run dev` — Vite dev server
- `npm run build` / `npm run preview` — production build (`tsc --noEmit` first) / preview
- `npm run test:blog` — validate the nine-question article, source manifest, sketch assets and run all Python / TypeScript examples (Python 3.10+ with SQLite FTS5 and Node.js 24).
- `npm run test:particles` — check particle bounds, local bounded disturbance and stable return to rest (Node.js 24).
- `npm run test:metrics` — check the live repo-metrics refresh (caching, staleness, partial and total failure, anonymous-quota cap) and the observatory's pure calculations in `src/lib/repoActivity.ts`.
- `npm run test:snapshots` (`test:starred` remains an alias) — validate both `src/data/projects.json` and `src/data/starred.json` against the runtime schema in `src/lib/repoSource.ts`, check browser fallback, and run collector failure/retry tests. Real snapshot validation remains separate from synthetic edge cases: never require live data to contain a particular case such as an empty activity array.
- `node scripts/fetch-github.ts` — regenerate `src/data/projects.json` from the GitHub API (requires the `gh` CLI, authenticated). Reads the pinned repositories of `zaimokuza-yoshiteru` in pin order via GraphQL, skips the repos listed in `EXCLUDE` (currently empty — this site's own repository is pinned and shown like any other work), then enriches each one through `scripts/lib/repo-metrics.ts`.
- `node scripts/fetch-github-starred.ts` — regenerate `src/data/starred.json` (requires the `gh` CLI, authenticated). The curated `WATCHED` list defines which repositories appear and in what order.

## Structure

- `src/data/profile.ts` — single source of truth for ALL copy (hero greeting and name, portrait description, project use-case descriptions, social links, experience timeline). Edit this file to change site content; the `Profile` interface documents the shape.
- `scripts/lib/repo-metrics.ts` — the shared build-time collector behind both JSON snapshots. Ordinary API failures abort before writing; statistics returning `202` with `{}` retry five times, five seconds apart. Unavailable statistics warn and retain the same repository's prior samples via `readPrevious`; successful empty responses clear them. Only a 404 from the latest-release endpoint falls back to the release list. CLI calls use a 30-second timeout and a 64 MB `maxBuffer`; snapshots replace their destination atomically after collection finishes.
- `src/data/projects.json` — generated by `scripts/fetch-github.ts`; do not hand-edit.
- `src/data/starred.json` — generated by `scripts/fetch-github-starred.ts`; do not hand-edit. Both snapshots are refreshed on a schedule and read by the browser at runtime, so their shape is a public contract: change a field and you must change `src/lib/repoSource.ts` with it.
- `src/components/` — `Nav`, `Hero`, `HeroParticles`, `Blog`, lazy-loaded `BlogArticle`, shared `SectionHeader`, shared `RepoCard` / `RepoFacts`, `Projects`, `Starred`, `RepoObservatory`, shared `GithubLink` / `ExternalArrow`, `Experience`, `Footer`.
- Blog metadata and shared UI copy live in `profile.blog` / `profile.articleUI`; posts use unique stable slugs, ISO dates and excerpts, sorted newest first. Long-form copy lives in `src/data/articles/<article>.md`, selected by each post's `article` key; legacy `paragraphs` remain supported. Home shows up to five posts; `#/blog` shows all, and `#/blog/<slug>` renders an article. `src/lib/navigation.ts` prefixes links with the deployment base.
- 观测 is its own page rather than a home section: `#/starred` opens the first curated repository, `#/starred/<owner>/<repo>` deep-links one, and the repository list above the observatory switches between them (`aria-current="page"` marks the open one). `src/lib/navigation.ts` exports `starredHref(fullName?)` for those links.
- Markdown articles render with `react-markdown` and GFM tables. An `example` fenced block containing `q01` through `q09` (plus `q04-cache`) renders Python/TypeScript tabs, copy and downloads from `src/data/articles/examples/`; these standalone teaching programs are excluded from browser TypeScript checking and executed by `test:blog`. Source quotations are verbatim, explained in Chinese, and tracked in `context-management.sources.json`; distinguish them from illustrative implementations. Sketches live in `public/blog/context-management/` and their runtime URLs are base-prefixed. Article dependencies and body load only when opening an article.
- Home displays all projects immediately, with a total in the section heading and no expansion control. Counts derive from data. `useRevealOnScroll` observes dynamically inserted content too.
- `src/interactions.ts` — `useRevealOnScroll` hook (IntersectionObserver adds `.visible` to `.reveal` elements, once).
- `src/index.css` — Tailwind v4 entry; design tokens live in `@theme`.
- `public/fonts/allura-regular.ttf` — signature font, now only for the hero name; its OFL license ships beside it as `public/fonts/allura-OFL.txt`.
- `public/fonts/kalam-regular.ttf` — handwritten font for every GitHub jump (`GithubLink`); its OFL license ships beside it as `public/fonts/kalam-OFL.txt`.
- `public/fonts/geist-mono-regular.ttf` — self-hosted font behind `font-mono-num`.
- All three fonts live in `public/` rather than `src/assets/` on purpose: Vite hashes CSS-referenced assets, so a hashed URL can never be written into a `<link rel="preload">` in `index.html`. A stable `/fonts/…` path is what makes the three preloads in `index.html` (built with `%BASE_URL%`) possible, and those preloads are what keep the hero name and the GitHub links from painting in a fallback face first. Allura and Kalam use `font-display: block`, so the browser waits for the real face instead of swapping; Geist Mono keeps `swap`.
- `.github/workflows/deploy.yml` — builds on push to `main` and publishes `dist` to GitHub Pages.
- `.github/workflows/refresh-starred.yml` — every 12 hours, runs `npm run sync:repos` with `GITHUB_TOKEN`, validates both snapshots with `npm run test:snapshots`, and commits both JSON files together only when changed. It deliberately does **not** rebuild or redeploy: GitHub never triggers workflows from a `GITHUB_TOKEN` push, and this design does not need it to, because the browser reads the file straight from `raw.githubusercontent.com`. The token is an ephemeral installation token minted per run — no secret is stored in the repository.

## Deployment / base path

The site is served from `https://<user>.github.io/zaimokuza/`, so `vite.config.ts` sets `base: '/zaimokuza/'` for `build` and `preview`, and `'/'` for dev. Any runtime URL to a `public/` asset or an internal link MUST be prefixed with `import.meta.env.BASE_URL` (see `portraitUrl` in `HeroParticles.tsx`) — hardcoded leading-slash paths 404 in production.

The three `@font-face` `src: url('/fonts/…')` entries are the deliberate exception: Vite rewrites leading-slash URLs **inside CSS** with `base` at build time (verified as `/zaimokuza/fonts/…` in `dist/assets/*.css`), and `index.html` uses `%BASE_URL%` for the matching preloads. Keep those three pairs in sync — a font URL that does not match its preload href makes the preload a second, wasted download.

## Dynamic GitHub Stars

- The deployed static page uses `src/hooks/useRepoMetrics.ts` and `src/lib/repoMetrics.ts` to refresh the volatile counters (stars, forks, open issues) of every displayed repository in the visitor’s browser. Cards render the bundled snapshot first. Cache v2 keeps a separate 15-minute timestamp per repository, preserves entries across page changes, and never renews failed entries; 403/429 stops the remaining requests. No token or backend is required.
- 首页 and 观测 re-read `projects.json` and `starred.json` respectively through `src/hooks/useRepoSnapshots.ts` + `src/lib/repoSource.ts`, so a snapshot refreshed by the cron shows up without a redeploy. The bundled file renders first and each fetch only starts on its corresponding page (neither runs on the blog); the fetched data replaces it only if every field validates, so a rate-limited, blocked or malformed response leaves the page exactly as it was. `raw.githubusercontent.com` caches for 5 minutes and sends `access-control-allow-origin: *`; do not switch this to jsDelivr, whose 7-day browser TTL would defeat the refresh.
- `App.tsx` scopes the metrics hook to the page on screen — the pinned works on home, the curated list on `#/starred` — so a visit only refreshes what it can actually display.
- Run `npm run test:metrics` to check caching, staleness, partial and total failure, and the request cap, plus the pure calculations in `src/lib/repoActivity.ts` (streaks, half-over-half trend, heat levels, byte formatting). The fetch scripts generate the metrics; Chinese descriptions live in `profile.projects` / `profile.starred`.

## Repository display (开源作品 · 观测)

- 开源作品 renders the shared card body from `RepoFacts` — a commit-activity sparkline, a language bar with legend, and a telemetry row — inside `RepoCard`, whose whole surface is the link to the repository. 观测 instead renders `RepoObservatory` (`Starred.tsx` adds only the switcher, heading and not-found fallback): a repository hero card, a six-metric strip, and eight numbered panels — 贡献日历, 每周提交量, 语言构成, 提交节律, 节律读数, 贡献者, 发布节奏, 最近提交. Cards stay on scale metrics alone — 最后推送 and the 最近提交 list belong to the observatory, never to a card.
- `RepoCard`'s head is a single `space-between` row: the repository name on the left, the release chip pinned to the top-right. The title carries `min-width: 0` so a long name wraps instead of squeezing the chip, the chip is `flex: 0 0 auto; white-space: nowrap`, and its `margin-top` is the half of the title's line-height minus its own box height that centres it on the title's first line — so the chip reads as a badge on the name rather than a second row. The concrete numbers are 16px / `leading-[1.7]` = a 27.2px line against a 23px chip box, so `margin-top: 2.1px`; `.project-row h3` in `index.css` declares the same size and the two must be changed together, since an unlayered `.project-row h3` silently beats the Tailwind utilities on the element. The head's `gap` is deliberately not reused as the title-to-body spacing; the card's own `gap` still sets that.
- The activity caption and its sparkline sit in a fixed-height block: the box is always reserved, so a repository whose whole life fits one weekly bucket keeps its caption on the same line as its neighbours instead of collapsing the row. The sparkline itself only draws once there are at least two weeks.
- The sparkline is the last N weeks of `/stats/commit_activity`, sliced to the weeks since repository creation so a young repo does not draw a long dead tail. The language bar uses a single ink at decreasing opacity rather than per-language colors; percentages are computed over the total bytes of all languages, so the segments deliberately do not fill the bar. Languages below 0.05% are dropped rather than shown as `0%`.
- 贡献日历 always occupies `CALENDAR_WEEKS` (53) columns: `alignWeeks` prepends zero-weeks before the first real week so recent data sits at the right edge, matching GitHub. All statistics still run on the unpadded array.
- 提交节律 / 节律读数 read `/stats/punch_card` — 168 cells indexed `weekday * 24 + hour`, Sunday first, times UTC, and GitHub caps the sample at the most recent 20,000 commits (so the panel total can be smaller than 贡献日历's). The quietest window is a ring search over every start hour, so it may wrap past midnight; `quietSegments` splits a wrapping window into two grid spans.
- 贡献者 / 发布节奏 / 最近提交 read `/contributors`, `/releases` and `/commits` from the snapshot rather than the API, so the browser never re-fetches them. 发布节奏 hides a release name whose digits match its tag, since most repositories name releases after the tag with a different prefix. 最近提交 links each short sha to `repo.url/commit/<sha>`.
- `repo.release` falls back to the newest pre-release when `/releases/latest` 404s. `ReleaseChip` takes `showPrerelease` (default `true`): 观测 marks that fallback with a `预览版` chip, 开源作品 passes `false` and shows the bare version, because a card is a scale metric rather than a release report. Totals for commits and contributors come from the `Link: rel="last"` page count.
- Shared labels live in `profile.repoUI`; per-section copy is `profile.projects` / `profile.starred`. Add a followed repository by adding it to `WATCHED` and to `profile.starred.entries`; removing it from `WATCHED` drops it from the page. The works list follows the GitHub profile's pinned repositories, so pin or unpin a repository to change it — re-pinning `mcp2skill` or `dsh-plugin-hub` restores their existing descriptions.

## Design tokens (`src/index.css` → `@theme`)

| Token | Value | Use |
|---|---|---|
| `bg-page` | `#f5f0e6` | page background (warm beige) |
| `bg-card` | `#f8f3ea` | cards — slightly LIGHTER than page |
| `bg-section` | `#ebe3d2` | tag pills / recessed fills (deepest) |
| `border-warm` | `#e3dac6` | hairline borders |
| `text-primary` | `#1f2329` | body text |
| `text-secondary` | `rgba(0,0,0,.55)` | muted text |
| `font-serif-main` | Georgia stack | display type (blog empty state); the hero name uses Allura and `GithubLink` uses Kalam |
| `font-mono-num` | Geist Mono stack | numbers, dates, repo names |
| `ease-out-strong` | `cubic-bezier(.16,1,.3,1)` | the house easing — use it for all motion |
| `radius-card` | `4px` | cards, panels, article blocks |
| `radius-chip` | `3px` | buttons, tags, pills, badges |
| `radius-hair` | `2px` | heatmap cells, bars, legend swatches |
| `radius-round` | `999px` | avatars only |

Layering rule: `bg-section` (darkest) < `bg-page` < `bg-card` (lightest). Never use pure white (`bg-white`) for surfaces.

Radius rule: the site is squarish, so nothing is a pill. Use the tokens (`var(--radius-card)` in CSS, `rounded-card` / `rounded-chip` in Tailwind) rather than literal values, and keep `radius-round` for avatars alone — they are the only circular element.

## Homepage layout

- Home shares a 960px `.site-frame` and one left alignment line. Hero uses a self-hosted Allura signature name beside a subtle 300px particle portrait; on mobile the smaller portrait remains beside the name. The nav is sticky (`sticky top-0 z-50`) on an opaque `bg-page` surface with a single hairline `border-b` spanning the full viewport width; the footer carries no divider and only the `.footer-sign` copyright, right-aligned in the same Kalam face as `GithubLink` so the two handwritten moments bookend the page. Every nav item is plain text at one weight and colour, including the GitHub link — no filled or outlined button in the nav. The entry for the page on screen carries `aria-current="page"`, and `.nav-link[aria-current='page']` turns it to `text-primary` and holds the same 1px underline open permanently, so the current page and the hover gesture read as one system. The GitHub link deliberately has no `nav-link` class and is never marked as current.
- Every link that leaves the site ends with `ExternalArrow`, a self-drawn SVG rather than the `↗` glyph: a glyph's shaft length is baked into whichever font draws it, so it could not be shortened on request. The SVG keeps the ink inside a `1em` square (`viewBox 0 0 10 10`) whose **bottom edge sits on the baseline**, at the same offsets the glyph's ink used to occupy (top 0.739em above the baseline, bottom 0.019em below), so an inline host keeps the historical `top: -0.42em` and lands in exactly the same place. It is `aria-hidden`, `position: relative` (so it never changes the host's height) and sized `max(0.55em, 7px)`. Two traps: (1) an `em` in `top` resolves against the **arrow's own** font-size, not the host's; (2) when the host is a flex container the box bottom no longer lands on the baseline, so the offset must be recomputed per host — `.gh-link` (17px host, 7.14px arrow) uses `-0.67em` and `.obs-tags` (11px host, 7px arrow) uses `-0.59em`, each reproducing the old glyph-era position. Keep the host's `gap` at `2px` — the component supplies the rest of the spacing.
- Every in-site jump to GitHub goes through `GithubLink` (`src/components/GithubLink.tsx`): the label is fixed at `profile.nav.github` in the Kalam handwritten font and only the `href` varies. It is used by the nav and the observatory's per-repository entry, so a GitHub entry looks identical everywhere. Add new GitHub entries with this component instead of a hand-written anchor. Its `font-size` is set by the **ink height**, not by eye: Kalam's ink is about 88% of its font-size, so `17px` renders the word about 15px high against the nav's 13px text — raising it further makes the nav entry shout over the menu.
- `--nav-h` (72px, in `@theme`) is the single source of truth for the sticky nav's total height — `box-sizing: border-box` keeps the hairline inside it. Everything that scrolls a target into view must clear the bar: home section headings use `scroll-mt-[var(--nav-h)]`, article `h2` use `calc(var(--nav-h) + 24px)`, and `.article-toc` sticks at that same `calc(var(--nav-h) + 24px)`.
- Home order is Hero → 开源作品 → 博客 → 履历. Blog and projects have headers above their content. Home blog entries use warm `bg-card` surfaces; projects use two columns of flat warm cards (one column below 640px). No section divider lines or subtitles. Preserve full descriptions and total counts. Projects display all entries; the home blog still shows up to five posts.
- A blog entry is a single `<a class="blog-row">` wrapping its own date/category, `<h3><span class="blog-title">` and excerpt — clicking anywhere in the row opens the post, exactly like `RepoCard`. Hovering anywhere in the row (not just the title text) turns the surface `#eee7d9` and underlines `.blog-title`, so the title feedback and the row feedback are one gesture. The archive reuses `.blog-row` as an editorial hairline list instead of cards: the row bleeds 16px into the frame gutter (`padding-inline: 16px; margin-inline: -16px`), the separator moves to an inset `::after` so it stays frame-wide while the hover fill bleeds, and hover fills with `bg-card`. Because `.blog-row` now declares its own `transition`, it must list `opacity` and `transform` alongside `background` — otherwise it would override `.reveal`'s transition and break the scroll fade-in.
- Work and education share one 履历 grid: a single list over `profile.experience`, two items per row (one column below 640px), each entry a `bg-card` card with a `experience-kind` pill (`profile.experienceKinds`) marking 工作 or 教育 beside its dates. No timeline ornaments.
- 观测 is not on the home page. It mirrors the blog archive: a full page with the section heading at 32px and a repository switcher (pill links on `bg-card`, active one on `bg-section`) above the observatory column. Neither top-level page carries a back link — the sticky nav already marks the current page with an underline, so `.back-link` exists only inside an article, where it returns to the blog list rather than the home page.
- The observatory reuses the card ink palette rather than GitHub's greens: the heatmap is five steps of `rgba(31,35,41,…)` (`.16 / .32 / .55 / .82`) on `bg-section`, and the language bar is one ink at decreasing opacity. Levels come from quartiles of the non-zero days (`heatThresholds`), so one 468-commit day cannot flatten every other day into a single shade.
- `src/lib/repoActivity.ts` holds the observatory's arithmetic — `activityStats`, `alignWeeks`, `movingAverage`, `monthLabels`, `rhythmStats`, `quietWindow`, `medianReleaseInterval`, `contributorShare`, `relativeTime`, `releaseTitle`, `formatBytes`, `formatSize`, `formatCompact`, `formatShare`, `daysSince` — and stays free of React and `import.meta.env` so `npm run test:metrics` can load it directly under Node.
- The heatmap is a CSS grid sized by an inline `--obs-weeks` (53 after `alignWeeks`, so recent data lands at the right edge): cells are capped at 25px, so a young repository shows a short calendar instead of one enormous square. `.obs-calendar-wrap` is a wrapping flex row, which lets the calendar and its footer stats share a line when the calendar is narrow and stack when it fills the width. On mobile the grid switches to `minmax(11px, 1fr)` with `overflow-x: auto`.
- The weekly panel draws one bar per week plus a 3-week moving average as a `preserveAspectRatio="none"` SVG polyline with `vectorEffect="non-scaling-stroke"`; the language panel's rows report bytes and percentages, and the segments deliberately do not fill the bar.
- 提交节律 is a 25-column grid (weekday labels + 24 hours) with a 168-cell body; the quiet band is an absolutely-positioned grid item spanning the quiet hours across all seven rows, so it sits behind the cells. On mobile its columns bottom out at `minmax(20px, 1fr)` and scroll, keeping the hour labels legible. 节律读数 is a two-column definition list of five readings. 贡献者 rows are a six-column grid (rank, avatar, name, share bar, count, percentage) whose bar and percentage drop on mobile. 发布节奏 pairs a tick strip positioned over the release-time span with a list of the newest versions, and 最近提交 lists the newest commits with short-sha links. 发布节奏 and 最近提交 both reflow to two rows on mobile.

## Interaction system

- **Hero portrait**: `HeroParticles` samples `public/images/hero-portrait.jpg` into Canvas 2D particles. Dark pixels form the portrait while light pixels leave the beige background visible. An explicit character outline excludes the floral background from sampling. Mouse proximity scrambles nearby particles in different directions with bounded displacement; springs bring them home without creating a radial hole. Native cursor throughout; no quote invert mask or globe. Touch and reduced-motion modes render a static portrait. Rendering pauses when settled, offscreen, or hidden.

- **Hover underlines**: `.nav-link` and the shared `.sweep-underline` draw their 1px underline as a `linear-gradient(currentColor, currentColor)` background whose `background-size` animates from `0 1px` to `100% 1px` — the nav is anchored at `50% 100%` so it opens from the middle outwards, `.sweep-underline` at `0 calc(100% - var(--sweep-gap))` so it sweeps left to right. A background is used instead of `::after` because every host is an **inline or fit-content** box: an absolutely positioned pseudo-element would size to the containing block rather than to the text run. `box-decoration-break: clone` gives each wrapped line its own sweep. `.sweep-underline` is worn by the blog title (`.blog-title`, `--sweep-gap: 3px`) and by the observatory card title (`.starred-head h3`, `--sweep-gap: 4px`); the gap is measured per font — it is what lands the line the right distance below the baseline, so recompute it if a host's font size or line-height changes. Two traps: (1) the hover trigger must sit on the row, not the title, so `.blog-row:hover .blog-title` and `.starred-card:hover .starred-head h3` are what flip the size; (2) any Tailwind `transition-*` utility on `.nav-link` overrides the rule's own `transition` shorthand and silently kills the animation, which is why the class string is just `nav-link hover:text-text-primary`.
- **Reveal on scroll**: add class `reveal`; stagger via inline `transitionDelay`.
- **Article navigation**: `useActiveSection` tracks the current H2 while scrolling and after content resizing; desktop and mobile contents share the hover style through `aria-current="location"`. Article pages show a floating `BackToTop` button after 400px, with keyboard focus restoration and reduced-motion support.

## Conventions

- Code comments are written in **Chinese**; this document and commit messages may be English/Chinese.
- **TypeScript strict mode** (`strict` + `noUnusedLocals/Parameters`); `tsc --noEmit` is part of `npm run build`. Data collectors, sync orchestration and related tests use TypeScript, with `tsconfig.scripts.json` enforcing strict checking and erasable syntax. Runtime imports include `.ts`; Node 24 runs them directly. Blog/particle test runners remain independent `.mjs` scripts.
- Tailwind v4 (via `@tailwindcss/vite`) with arbitrary values (`text-[15px]`); theme tokens only through `@theme`, no `tailwind.config.js`.
- Keep components presentational; no state management library.
